## 一、系统概述

本次迭代把专家模式中"界面可配、但当前对真实扫描零影响"的三项配置真正接线到引擎，并建立深度契约测试锁定行为，杜绝回归。改动严格限制在 Core（可单测）与专家模式窗口的既定调用点，不触碰主窗口扫描逻辑。

## 二、三项接线的现状与设计

### US-01：ServiceDetectTimeout（服务识别超时）接线

**现状（缺陷）**：`PortScanner.IdentifyServiceVersionAsync` 使用硬编码常量 `ServiceVersionTimeout = 600`；`ScanTcpPortAsync`（L484）与 `RetryTcpPortAsync`（L569）均忽略界面配置。滑块 500–10000ms 无任何效果。

**设计**：
1. Core 新增纯模型 `NetSecurityScanner.Models.ServiceDetectionConfig`（置于 `ScanPolicy.cs`）：
   - `bool Enabled`、`int DetectTimeoutMs`、`int Tries`
   - 静态工厂 `FromIntensity(bool enabled, int intensity, int detectTimeoutMs)`：把 `ExpertScanConfiguration.ServiceIntensity` 的取值映射为探测深度（见 US-04），并把 `ServiceDetectTimeout` 落到实处。
2. `ScanPolicy` 增加可空属性 `ServiceDetectionConfig ServiceDetectionConfig`（默认 null → 保持既有行为，主窗口扫描零回归）。
3. `PortScanner`：
   - `ScanTcpPortAsync(..., ServiceDetectionConfig serviceDetection = null)`、`RetryTcpPortAsync(..., ServiceDetectionConfig = null)` 增加可选末参。
   - 新增私有 `IdentifyServiceVersionWithPolicyAsync`：当 `serviceDetection.Enabled && Tries>0` 时按配置的时间与尝试次数循环探测；null 时回退到原 1 次 / 600ms 逻辑。
   - `ScanTcpPortsAsync` 把 `scanPolicy?.ServiceDetectionConfig` 下传。
4. Desktop `BuildScanPolicy(config)` 设置 `ServiceDetectionConfig = ServiceDetectionConfig.FromIntensity(config.ServiceDetection, config.ServiceIntensity, config.ServiceDetectTimeout)`。

**数据流**：`ExpertScanConfiguration.ServiceDetectTimeout` → `BuildScanPolicy` → `ScanPolicy.ServiceDetectionConfig.DetectTimeoutMs` → `PortScanner.IdentifyServiceVersionWithPolicyAsync` → 实际的 socket 读超时。

### US-04：ServiceIntensity（服务检测强度）接线

**现状（缺陷）**：`ServiceIntensity` 仅被 `NmapCommandBuilder` 翻译成命令，内置引擎不消费。

**设计**：强度分级映射只读地让高强度 → 更多 banner 探测尝试 + 更宽松单次超时：

| 强度 intensity | Tries | 说明 |
|---|---|---|
| 0（或检测关闭） | 0 | 跳过 banner（快速可达性） |
| 1–3 | 1 | 浅探测 |
| 4–6 | 2 | 中探测 |
| 7–9 | 3 | 深探测 |

- 单次探测超时按强度线性放宽：`timeout * (1 + intensity * 0.055)`（intensity=9 ≈ 1.5×），换取慢速服务更可能被识别。
- 交由纯函数 `ServiceDetectionConfig.FromIntensity` 实现，便于无网络单测。

**兼容性承诺**：`ServiceDetection` 复选仍是总开关；内置引擎仅在强度≥1 时启用 banner 抓取。主窗口调用方（未传 ScanPolicy 或未设置 ServiceDetectionConfig）行为不变。

### US-03：输出格式（JSON/HTML/CSV）真正影响自动保存

**现状（缺陷）**：专家模式自动保存分支（`ExpertModeWindow` L1488-1498）恒写 `.json`，三个勾选框被忽略。

**设计**：在自动保存分支按勾选生成本目标独立的三种文件（时间戳后缀，多目标不覆盖）：
- `OutputJson` 勾选（或三者均未勾选以保持向后兼容）→ 写 `.json`
- `OutputHtml` 勾选 → 写 `.html`
- `OutputCsv` 勾选 → 写 `.csv`
- 三种序列化逻辑抽为自包含的四个私有方法（`SerializeJson` / `SerializeHtml` / `SerializeCsv` / `WriteAutoSaveOutputs`），HTML/CSV 使用脚本不可执行的纯转义。
- 扫描历史库入库逻辑（`_jsonDatabaseService.SaveScanResultAsync`）保持不变。

## 五、技术选型决策记录

| 技术点 | 选项 | 选择 | 理由 |
|--------|------|------|------|
| 强度→深度映射载体 | UI 硬编码 / Core 纯函数 | Core 纯函数 `FromIntensity` | 脱离 WPF 可单测，单一真相源 |
| 引擎通道 | 仅 Rust / ScanPolicy+ScanProfileConfig 双通道 | 双通道 | C# 内置引擎走 ScanPolicy；Rust 走 ScanProfileConfig，二者都真正携带 |
| 探测深度 | 状态机 / 简单计数 | 简单 keeps 计数 tries | 满足"强度越高探测越深"，复杂度最小、可测 |

## 六、安全设计

- HTML/CSV 输出对特殊字符做 HTML 转义，避免保存文件被当作可执行脚本利用。
- 不引入硬编码密钥/连接串；不触碰授权码校验路径（本仓库含 LicenseKeyGenerator，须保持隔离）。
- banner 探测重试间隔加退避上限（min(50ms, timeout/2)），避免高强度形成激进探测。

## 七、风险

🔺 R1：`PortScanner.ScanTcpPortAsync` 有多处内部调用点——通过"新增可选末参、默认 null"保持二进制兼容，零回归。
🔺 R2：契约测试守卫会把本次"未执行接线"视为失败——采用先改代码后改测试的顺序，避免测试先行红。
