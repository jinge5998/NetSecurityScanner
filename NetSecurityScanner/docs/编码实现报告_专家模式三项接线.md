## 二、关键业务逻辑描述与算法

### 2.1 强度→探测深度分级映射（US-04，纯函数 [FromIntensity](file:///d:/360安全浏览器下载/软件开发备份/网络安全漏洞扫描/NetSecurityScanner/src/NetSecurityScanner.Core/Models/ScanPolicy.cs#L338-L349)）

```
clamp(intensity, -1, 9)
enabled=false 或 clamp<1  →  Tries = 0（仅端口可达性，跳过 banner）
clamp 1-3  →  Tries = 1（浅）
clamp 4-6  →  Tries = 2（中）
clamp 7-9  →  Tries = 3（深）

单次探测超时：base = detectTimeoutMs>0 ? detectTimeoutMs : 600
timeout = max(1, round(base * (1 + clamp * 0.055)))   // 约 1.0× → 1.5×
```

### 2.2 引擎侧多尝试 banner 探测（US-01，[IdentifyServiceVersionWithPolicyAsync](file:///d:/360安全浏览器下载/软件开发备份/网络安全漏洞扫描/NetSecurityScanner/src/NetSecurityScanner.Core/Services/PortScanner.cs#L599-L610)）

- `serviceDetection` 为 `null` 或 `Enabled=false` 或 `Tries=0` → 回退旧路径（1 次 / `ServiceVersionTimeout`），零回归。
- 启用时：每次使用 `DetectTimeoutMs` 超时，读失败则按 `Tries` 重试，retry 间加退避上限 `min(50ms, timeout/2)`，保留最后一次结果。
- 入口点 [ScanTcpPortAsync](file:///d:/360安全浏览器下载/软件开发备份/网络安全漏洞扫描/NetSecurityScanner/src/NetSecurityScanner.Core/Services/PortScanner.cs#L452) 与 [RetryTcpPortAsync](file:///d:/360安全浏览器下载/软件开发备份/网络安全漏洞扫描/NetSecurityScanner/src/NetSecurityScanner.Core/Services/PortScanner.cs#L554) 均以可选末参接收；`ScanTcpPortsAsync` 统一透传 `scanPolicy?.ServiceDetectionConfig`（见 [PortScanner.cs#L110](file:///d:/360安全浏览器下载/软件开发备份/网络安全漏洞扫描/NetSecurityScanner/src/NetSecurityScanner.Core/Services/PortScanner.cs#L110)）。

### 2.3 自动保存多格式输出（US-03，[WriteAutoSaveOutputs](file:///d:/360安全浏览器下载/软件开发备份/网络安全漏洞扫描/NetSecurityScanner/src/NetSecurityScanner.Desktop/Views/Views/ExpertModeWindow.xaml.cs#L1873-L1896)）

- 按 `OutputJson/OutputHtml/OutputCsv` 勾选分别写 `.json/.html/.csv`；三者均未勾选时**回退写 JSON**（兼容旧版）。
- HTML：全量文本经 `WebUtility.HtmlEncode` 转义，生成不含可执行脚本的只读报告。
- CSV：按 RFC 4180 对含逗号/引号/换行字段用双引号包裹并转义（`CsvEscape`）。
- 保持「扫描历史入库」逻辑不变，仅在自动保存分支扩展独立文件输出。

### 2.4 Rust 引擎通道（US-01/04）

`ScanConfigMapper.ToScanProfileConfig` 将界面值映射到 `ScanProfileConfig.ServiceIntensity`（`clamp(0,9)`）与 `ServiceDetectTimeoutMs`（`>0 ? 值 : 0`），供 Rust 引擎消费。

### 与设计文档的差异及原因

1. `ServiceDetectTimeout` 对 Nmap 命令生成**无效**：验证 `NmapCommandBuilder` 仅读取 `ServiceIntensity`（`--version-intensity`），不读超时字段。原设想「同时影响命令生成」不成立，已按事实修正契约测试断言并记录在设计文档第八节。
2. US-03 的核心行为落在 WPF 端，不在 Core 契约测试观测范围内，故契约分类中 `OutputJson/Html/Csv` 仍标识「仅命令生成」并注明原因——这是文档化边界，非遗漏。
