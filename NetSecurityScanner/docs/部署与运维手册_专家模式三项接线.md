## 二、构建说明（dotnet publish）

### 2.1 框架依赖发布（推荐，体积小）
```powershell
dotnet publish src/NetSecurityScanner.Desktop/NetSecurityScanner.Desktop.csproj `
  -c Release -r win-x64 --self-contained false -o ./release/fde
```
- 目标机需安装 **.NET 6.0 Desktop Runtime (win-x64)**。
- 产物含 `NetSecurityScanner.exe`、`Data/*.json`（`CopyToOutputDirectory=PreserveNewest` 自动复制）。

### 2.2 自包含 / 单文件（离线分发）
```powershell
dotnet publish src/NetSecurityScanner.Desktop/NetSecurityScanner.Desktop.csproj `
  -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o ./release/sc
```
- 免装运行时；体积更大、启动略慢；WPF 单文件在个别杀软下可能误报，需签名或加白。

### 是否新增测试
> `dotnet test src/NetSecurityScanner.Core.Tests` 覆盖全部核心契约（含本次 US 生效性断言）；发布前 CI `build-and-test` 已执行，无需额外部署测试。

### 版本
以 `Desktop.csproj` 的 `Version/AssemblyVersion = 1.0.2.4` 为准；发布前如需升版，改三处并 tag。

## 三、数据与配置管理（重点）

| 项 | 位置 | 说明 | 运维注意事项 |
|----|------|------|--------------|
| 漏洞库 | `Data/StaticVulnerabilityDatabase.json` | 引擎内置规则 | 随发布目录复制；升级新库应做格式兼容校验 |
| 插件策略 | `Data/PluginPolicy.json` | 扫描插件启用策略 | 同上 |
| 基础配置 | `App.config` | 应用级配置 | 明文，**严禁存放密码/密钥** |
| 专家模式配置 | 界面 → 系统内保存 | US-01/03/04 依赖项的取值 | 升级后若默认值变化，提示用户确认 |

**安全约束（强制）**：本项目禁止硬编码连接字符串/密钥；如后续引入需凭据的能力，一律走环境变量或 Windows 凭据管理器（`CredentialManager`），不得写入 `App.config`。

## 四、CI/CD（既有流水线）

位于 `.github/workflows/ci.yml`：
1. **build-and-test**：`setup-dotnet`（6.0.x + 8.0.x）→ restore → build Core/Desktop/Tests → `dotnet test`（含 `XPlat Code Coverage`）→ 上传覆盖率产物。
2. **security-scan**：`dotnet list <proj> --vulnerable` 对 Core/Desktop/Tests 三方检查依赖漏洞。

> 本次改动不触碰工作流；新断言（`ExpertScanConfigEffectivenessContractTests`）默认纳入该流水线回归。

## 五、监控与告警（桌面应用）

非 Web 无 HTTP 健康端点，采用桌面形态的观测手段：
- **程序日志**：扫描/异常写入日志（主窗口 `AppendLog` + 控制台）；故障排查以日志为准。
- **Windows 事件日志**：异常崩溃可由目标机系统事件查看器捕获（若接入全局异常钩子）。
- **进程与资源**：任务管理器观察 CPU/内存；扫描并发/超时受 `RateLimitConfig` 约束，无需额外限流设备。

## 七、回滚方案

- **发布目录法（推荐）**：保留上一版本目录 `release/v1.0.2.3`，新版本失败时切换回来并恢复原启动快捷方式即可。
- **数据兼容**：若更新了 `StaticVulnerabilityDatabase.json`，回滚时同步还原旧版数据文件，避免格式不匹配。
- **版本标注**：升级前在发布目录建立 `RELEASES 记录`（版本、日期、改动条目），便于快速定位可回滚版本。

## 八、常见故障排查命令

```powershell
# 环境自检：确认运行时版本
dotnet --list-runtimes

# 确认发布产物
Get-ChildItem ./release/sc

# 快捷初始化新方案（当前仓库是基于 src/NetSecurityScanner.sln）
dotnet restore src/NetSecurityScanner.sln

# 复跑核心契约测试（US 生效性锁定）
dotnet test src/NetSecurityScanner.Core.Tests/NetSecurityScanner.Core.Tests.csproj -c Release `
  --filter "FullyQualifiedName~ExpertScanConfigEffectiveness"
```

- 应用无法启动 → 先 `dotnet --list-runtimes` 核对 Desktop Runtime；再检查 `Data/` 是否随发布复制。
- 扫描结果异常 → 检查专家模式配置教验默认值是否被覆盖。

✅ DevOps 签收复核：构建/发布可复现、数据依赖明确、回滚可行、无密钥落地。可进入阶段 6 收尾。
